# ASTERIX public API proposal

**Tier:** Preview proposal for implemented CAT021/048/062 decode/encode capabilities, pending the §8 evidence bundle. CAT034 is **unsupported and outside the proposed 0.1 scope** because no CAT034 codec/module exists in the reviewed crate; there is no CAT034 API to tier. Do not describe absent functionality as an Experimental implementation.

**Proposed public surface:** `decode_block(bytes, DecodeOptions) -> Result<(Block, consumed), DecodeError>`, `decode_stream(bytes, options) -> Result<Vec<Block>, DecodeError>`, and `encode_block(block, EncodeOptions) -> Result<Vec<u8>, EncodeError>`. Keep current `Block`/category records and raw-item preservation behind a format-neutral public facade. Options must explicitly select CAT021 edition (2.4 or 2.7); defaulting silently to 2.7 is undesirable for a public interface. Do not expose internal FRN table implementation as a stability promise.

**Source-backed contract:** ASTERIX Part 1 Ed 3.1 framing; CAT021 Ed 2.7 and 2.4; CAT048 Ed 1.32; CAT062 Ed 1.21. CAT021 positions: I021/130 resolution 180/2^23 degrees; I021/131 180/2^30 degrees. Time items: 2^-7 seconds since midnight UTC; selected fields use their specified item scales (e.g. CAT021 track angle 360/2^16 degrees; CAT062 I062/105 position 180/2^25 degrees; CAT062 I062/185 velocity 0.25 m/s). Public values should preserve raw integer counts and provide named conversion functions, avoiding implicit float-only values. Time is day-relative UTC, not an absolute date; caller supplies date/day rollover context.

**Bounds/refusals:** current max block 65,535 bytes; max records per block derived from framing; 32 FX extensions; 255 repetitions; 8 primary compound octets. Errors identify category, record, item, subitem, and byte offset. Keep reserved enumeration codes readable; refuse structural violations, invalid values and encoder range/duplicate-item errors. Clarify stream-absolute offsets versus per-block offsets in the final API.

**Gaps/stability:** CAT034 is absent, with no decoder or encoder. CAT021/048/062 have typed records, raw items, category-specific round-trip facilities and source tests/proofs, but CORE_LIBRARY_SPEC Stable evidence (24h fuzz, Kani where applicable, reviewed mutation results, no-panic review, cross-arch bits, published vectors and Rust/Python examples) is not established by source inspection. Keep implemented categories at Preview until each package/profile is evidenced; only then separately review any future CAT034 implementation.
