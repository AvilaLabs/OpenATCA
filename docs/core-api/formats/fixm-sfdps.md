# FIXM / SFDPS public API proposal

**Tier:** Preview for decoding; Experimental for encode/publish.

**Proposed public surface:** `Decoder::new(limits, DecodePolicy)`, where policy explicitly carries the expected namespace/profile and time filter, then `decode_document(doc, exact_source_bytes, &mut Events) -> Result<Summary, DecodeError>`. Provide a separate allocation-free `prescan` helper only if its semantics remain documented. Expose typed field presence/errors, unknown-path counts, accepted/rejected counts, and capacity/truncation status. Do not publish internal seal/window policy (`oa-sealed`) as a format-facing type; replace it with a public format policy that does not expose internal filtering policy.

**Source-backed contract:** FIXM 3.0 core plus FAA NAS 3.0 extension; accepted document root `MessageCollection` in `http://www.faa.aero/nas/3.0`, message type `FlightMessageType`. Message and position timestamps are strict ISO-8601 UTC parsed to Unix milliseconds; position time is distinct from message timestamp and any receive-time supplied by an outer transport. Position is decimal degrees converted to E7, altitude to feet, speed to 0.1 knot, ICAO address to 24-bit integer. Units come from `uom`; unknown units are field errors. The parser does not provide an encoder.

**Bounds/refusals:** default 50,000 XML elements, 2,048 route bytes, 256 unknown-path entries, 160 bytes per retained unknown path. Whole-document capacity errors are atomic; optional prefix decode records `not_decoded`. Whole-message refusals include missing/bad GUFI, missing/bad timestamp, wrong message type, duplicate flight. Present malformed fields produce error bits and absent values; unknown XML paths are counted, not fatal. Error API should include byte/line positions from `oa-xml` spans for structural errors and field path plus source location for semantic errors; the current public `Reject` list is categorical and does not preserve a source position.

**Encode/publish gap (J1f):** no FIXM encoder, publisher, SWIM envelope writer, or outbound ACK/REJ service exists in this crate. A decoder and field model do not satisfy publication. A future encoder needs an explicitly pinned FAA profile, schema validation, deterministic namespace/prefix and ordering rules, round-trip policy for unknown elements, typed field errors and byte-positioned serialization failures. Use synthetic schema-based vectors. `oa-fixm` currently depends on `oa-sealed`, a project-internal crate, contrary to the Core boundary; public API extraction must remove that dependency.
