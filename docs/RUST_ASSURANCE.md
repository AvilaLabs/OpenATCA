# Rust assurance record

This record separates requirement validity, bounded proof, runtime testing, allocation checks, replay conservation, and physical-truth validation. Each answers a different question. Results are scoped to the stated source, harness, bounds, inputs and tools; a passing proof of a mistaken requirement is not evidence of intended behavior.

## Current verification results

**Kani 0.68.0 registry:** 43 enabled obligations have source-bound local PASS records; the registry contains 48 entries, including five disabled experiments. The [machine-readable record](../validation/rust-proof-status.json) preserves the earlier 22 results and the 21 added results in distinct frozen source groups. This is a cumulative local record, not one fresh-checkout run. CI reruns the complete enabled registry on each proposed revision. After the core/shell split moved `mono_split.rs` to `crates/oa-replay/src/core/`, the registered harness id is `core::mono_split::proofs::split_matches_i128_for_the_full_typed_domain`; that one proof was rerun locally (PASS, nine covers satisfied) and is recorded as a new source group in the status file, with the earlier record kept. The counts above (48 registered, 43 enabled) are unchanged.

Five added in-order caller proofs independently vary and dirty the selected current-filter, anchor-filter, ring, metadata or statistics projection before modeled refusal. Production capture and restore calls remain in the path. These establish each selected projection through the actual caller; their differing other prestate fields do not establish an arbitrary simultaneous-state theorem.

Late replay uses six postcondition proofs for each output capacity: current filter, anchor filter, all ring entries and indexing metadata, other track metadata, statistics with one saturating numerical-refusal increment, and output. Each capacity's six proofs share the same two-event fixture, symbolic inputs, stubs and actual production call. Their conjunction establishes the complete declared rollback postcondition for that fixture. Two separate reachability proofs confirm an output attempt before later numerical refusal, for append capacity 2 and overflow capacity 1. Before/after track observations read raw columns independently of production transaction capture. The filter seam models first success and later refusal; this does not prove nonlinear filtering, arbitrary prestates or other histories.

The late family uses reviewed scoped loop bounds (3, 2, 2, 3) within the unchanged global unwind of 16. Every unwinding assertion remains required. The runner checks exact closed preset arguments, fixture/source locations and actual loop diagnostics, including the base scan's observed completion before its bound. CBMC loop ids embed the crate disambiguator, which cargo recomputes whenever any dependency changes, so the registry stores them as templates. Before each run the runner compiles the harness (`--only-codegen`), lists the loops of the goto program with `goto-instrument --show-loops`, and requires the loops of `update_late` to be exactly the registered set (one disambiguator, indexes 0-3, registered file, function and source line); any moved, missing or extra loop fails the run. Only the discovered exact ids reach `--unwindset`, the discovery (ids, locations, goto binary and listing hashes) is recorded in the evidence, and the log check then confirms the bound at those ids and locations. A stale selector, incomplete report or resource failure cannot pass acceptance.

The runner invokes and records Cargo 1.89.0. Generated loop identities differed between local and CI builds even with that Cargo version. The current presets explicitly register both observed identity families and require one complete, consistent family in the actual diagnostics; unknown or mixed identities fail. CI at `4785bf3` rejected fourteen loop bindings while all 43 raw reports passed. That CI result remains failed. Two real local checks and an intended rollback counterexample validate the corrected runner; the complete exact-revision CI run remains a separate requirement. CI stops after its first non-passing proof, records the remaining obligations as `NOT_RUN`, and retains the failure diagnostics.

Two full-64 sensor proofs cover the canonical full-table fixture with IDs 0..63: existing-ID maximum-time update, and fresh ID 64 evicting the first oldest entry. Stored/report timestamps span all i64 values and the eviction counter spans u64. The first-argmin witness exists for every nonempty finite timestamp array; the strict-earlier condition selects its unique first minimum. This pair covers the original finite fixture contract, not arbitrary table layouts or every u16 ID assignment.

The combined overflow attempt exhausted Kani-driver memory without producing a result JSON; the current assertion-only combined append configuration was not run. ## Reproduce the checks

Install the pinned tools shown in [.github/workflows/rust-proofs.yml](../.github/workflows/rust-proofs.yml), including product Rust 1.89.0 and Kani 0.68.0. Run the registry sequentially from the repository root, with a new evidence directory:

```sh
python3 tools/test_kani_validation.py
python3 tools/test_rust_proof_suite.py
python3 tools/test_prepare_rust_proof_controls.py
python3 tools/rust_proof_suite.py --repo "$PWD" \
  --registry "$PWD/tools/rust_proofs.json" \
  --out /tmp/oa-rust-proof-evidence --target-dir /tmp/oa-rust-proof-cache --fail-fast
```

The runner records source and tool identities, exact commands, required branch covers, declared stubs, raw results, and resource outcomes. It refuses partial reports, mismatched bindings, failed assertions/unwind checks, and missing required covers. A compiler-cloned cover site must have a satisfied instance; an unsatisfiable site alone cannot pass. Build caches are namespaced by the resolved checkout path, and solver runs are offline and single-job.

The [Creusot package instructions](../validation/oa-creusot-check/README.md) describe its separate pinned toolchain and direct production-source import. It adds no product dependency. `tools/prepare_rust_proof_controls.py` freezes source and prepares isolated one-site negative-control checkouts; provisioning alone is not a proof or a detected control.

## Requirements and claims

Requirements specify the intended property; tests exercise chosen production executions; bounded proof harnesses quantify over inputs admitted by their assumptions and unwind limits. Keep requirements linked to tests/proofs, and review the oracle independently. If a proof stubs a decision, its conclusion is conditional on that decision. Tests remain necessary for caller wiring and realistic replay. For state restoration, compare against an independent pre-state that uses non-default/arbitrary field values; do not let the expected state share mutations with the transaction under test.

## Tool boundaries

- **Kani**: bounded symbolic checking with explicit assumptions, stubs, loop limits and configured capacities. A passing bounded harness is not induction over arbitrary histories or proof of code it does not reach.
- **Creusot**: deductive contracts for the directly imported production helper. Record toolchain, solver, trusted model and source identity; a helper proof does not verify its caller or system.
- **Miri/sanitizers**: complementary checks on executed paths and supported operations, not exhaustive model checking.
- **Allocator/performance runs**: observations on named routes and hardware/configurations; controls validate the measurement, not unexecuted routes. Refused, dropped or overflowed work must remain visible.
- **Replay and independent truth**: evidence about conservation and empirical behavior. Verifiers cannot establish truth-source independence or model validity.

## Release state

The assurance/release gate remains **OPEN**. Global allocation/work-budget coverage, matched ERAM comparison, and independent holdout/physical truth remain unresolved. The accepted Kani subset, Creusot helper proof, and runtime tests do not close those project-level claims or establish that the entire project is verified.
