# Open unknowns

Every entry says why it is unknown and what settles it.

| ID | Area | Unknown | Why | Next step |
|---|---|---|---|---|
| UK-001 | Boundaries | Whether NASR ARTCC boundary points are joined by geodesics or rhumb lines | No FAA document found states it; JO 7900.1F says only "straight lines" | Model stores both and reports the separation (OA-ASP-005); ask FAA AIS during outreach |
| UK-002 | CIFP | Fields parsed but not verified against a second source: header CRC; ER col 44; PD/PE/PF cols 26, 45-47 (RNP), 117, 119, 120; localizer cols 75-83; PG cols 91-95; PA cols 62-70, 82-85; RF arc radius scale; southern-hemisphere MORA convention; altitude description codes; TCH indicator values D/R; UR continuation types other than C | No public second source checked yet for these fields | Verify each against CIFP Readme exceptions and charted values before any later milestone uses the field; until then the model does not consume them |
| UK-003 | Procedures | Radar-vector SIDs (for example O'HARE NINE at KORD, computer code NOT ASSIGNED in NASR) exist in NASR but are not coded in CIFP | CIFP codes only procedures with a defined path | Model takes such procedures from NASR, marked as having no coded legs |
| UK-004 | SWIM latency | How late SCDS data arrives compared with when the source produced it. Measured 2026-11-14 on one 60 s sample per feed, with the receiver clock NTP-synchronised: SFDPS arrives a steady 58–61 s after each `flight` element's `timestamp`; TBFM 7–9 s after `envTime`; TFMS 1–8 s after `sourceTimeStamp`, which has whole-second resolution | It is not known whether SCDS deliberately delays public distribution, or whether each timestamp marks generation, last update or something else. A backlog draining would make the lag shrink over the run; it stayed steady | Measure continuously with `oa-feed`'s latency histogram over hours, and confirm the field meanings and any distribution delay from FAA SCDS and SFDPS documentation. Until settled, no function may treat SCDS data as current to better than the measured lag |
| UK-005 | Time and position integrity | Where trustworthy time and position come from when GNSS is jammed or spoofed. ADS-B positions and the receiver clocks that time-stamp them both depend on GPS, and GNSS interference is reported to be increasing | No design yet; radar gives independent position but not independent time, and the comparator assumes a correct clock | Survey FAA and EUROCONTROL GNSS-interference reporting and the time-source backups in use (atomic references, network time, eLoran); define how a facility detects a wrong clock and quarantines GNSS-derived inputs that disagree with radar (principle 2a) |
| UK-006 | Backbone-independent links | Which path, if any, can carry essential data between facilities when the shared network fails (SCOPE principle 8) | Capacity, latency and approval of satellite or HF data links for ATC use not studied | Size the essential data per facility, then survey existing aviation satellite and HF data services |
| UK-007 | Flight data from its source | Where a facility node gets flight plans, amendments and interfacility coordination without depending on another facility's automation; SWIM's SFDPS is ERAM output, so it fails with the centre that produces it (docs/NODE_NETWORK.md) | Public documents (2026-11-19 survey) show every flight-data path ends at one centre's ERAM: filed plans are addressed over NADIN/AFTN to the departure centre (ERAS Guide v3.2 2.1), and controller amendments, assigned altitudes, beacon assignments and handoff state exist only in the controlling centre until forwarded. The hubs (NADIN, the NAM gateway) do not depend on any one centre. In 2014 every neighbour processed Chicago's flight plans by hand for the whole outage (OIG AV-2015-112). No public document describes automatic re-addressing of a failed centre's plans | Read NAS-IC-82424301-01 (NADIN) for re-addressing and JO 7110.10DD for filer fallback; specify node subscription to plans addressed to the centres it backs up, and controller entries as replicated engine inputs once operational |
